# WAF：七步世界分析法

## Overview

用这套框架分析一个事件、问题或变化时，目标不是把话说满，而是从事实一路推进到行动：先看清发生了什么，再判断为什么会发生、它嵌在什么系统里、会影响谁、体现了什么长期规律、未来可能怎么走，以及自己该如何应对。

优先产出高密度判断，避免空泛评论。始终分清四组边界：事实 vs 推测、症状 vs 原因、可能性 vs 概率、观点 vs 行动。

## Output Contract

默认按七个编号部分输出，标题直接使用：

1. Fact
2. Cause
3. System
4. Impact
5. Principle
6. Prediction
7. Decision

除非用户明确要求更短，否则每一部分都要有实质内容。若事实不完整，也不要停在泛泛而谈；应明确区分：

- 已知事实
- 合理假设
- 仍然未知

对于时效性强的主题，先核实事实，再进入分析。

## Step 1: Fact

先回答：到底发生了什么？

最少要交代四件事：

- 关键事件或变化是什么
- 主要参与者是谁
- 时间范围是什么
- 和之前相比，究竟变了什么

推荐写法：

- 用一句话概括事件
- 列出 3-6 条已知事实
- 单独写出假设和未知点

常见错误：

- 把判断当事实
- 一上来解释原因，跳过事实澄清
- 只写结论，不写变化前后

## Step 2: Cause

回答：为什么会发生？

连续追问 3-5 次 why，直到找到更稳定的驱动因素。通常至少拆成三层：

- 表层诱因：直接触发了什么
- 中层机制：流程、激励、约束如何让事情变成这样
- 深层驱动：更底层的利益、能力、资源、制度、心理或技术条件

优先寻找“能够解释多个表面现象”的原因，而不是给每个现象分别编一个理由。

常见错误：

- 把结果再描述一遍，误当原因
- 找到第一个 plausible answer 就停
- 只归因于个人品质，忽略结构性约束

## Step 3: System

回答：这件事主要属于哪个系统？是否同时受其他系统牵引？

先给出一个主系统；如果有必要，再给 1-2 个次系统。六大系统如下：

| System | 关注点 |
| --- | --- |
| Human | 个体动机、认知、情绪、信任、能力 |
| Organization | 团队分工、流程、权责、治理、激励 |
| Society | 文化、舆论、法律、制度、社会规范 |
| Economy | 价格、成本、竞争、资本、资源配置 |
| Technology | 工具、基础设施、性能边界、技术扩散 |
| Nature | 地理、气候、能源、生物、物理约束 |

输出时不要只报分类名，必须补一句判断依据，例如：

- 主系统：Organization，因为核心问题来自权责和协作失灵
- 次系统：Human，因为关键人物的信任瓦解放大了问题

常见错误：

- 强行只选一个系统，忽略交叉作用
- 只贴标签，不解释为什么属于这个系统

## Step 4: Impact

回答：它会影响谁？影响通过什么路径传导？

至少覆盖：

- 直接受影响者
- 间接受影响者
- 短期影响
- 中长期影响

如果主题适合，继续区分：

- 谁受益，谁受损
- 一阶影响，二阶影响
- 个体、组织、行业、社会四个层级

常见错误：

- 只讲一个主体，不讲扩散链条
- 只讲“影响很大”，不讲影响机制

## Step 5: Principle

回答：它体现了什么长期规律？

把事件上升为 1-3 条可迁移的规律。规律要能脱离具体案例继续成立。优先使用这种句式：

- 当 X 与 Y 同时出现时，Z 往往会发生
- 在资源/信息/权力不对称的系统里，A 往往比 B 更先出现
- 当短期激励持续压过长期能力建设时，系统通常会走向 C

好规律应当：

- 比个案更抽象
- 比鸡汤更具体
- 能帮助理解下一次类似事件

常见错误：

- 写成空话，例如“变化是唯一不变的”
- 只是把前文换个说法复述一遍

## Step 6: Prediction

回答：接下来会怎样？

必须至少给出三种未来：

- 乐观
- 中性
- 悲观

每一种未来都要包含：

- 概率
- 触发条件
- 早期信号

如果没有充分依据，不要给特别精确的数字；但应让三种情景的概率加总约为 100%。

推荐写法：

- 乐观：25%。如果 A、B、C 发生，事件可能走向 ...
- 中性：50%。如果主要约束没有根本改变，最可能出现 ...
- 悲观：25%。如果 D、E 被触发，系统可能滑向 ...

常见错误：

- 只写可能性，不写概率
- 把自己希望发生的结果当成高概率结果
- 不写触发条件，导致预测无法验证

## Step 7: Decision

回答：我怎么办？

先明确决策主体是谁。如果用户身份不明确，做一个最合理假设，并说出来，例如“以下建议默认站在创始人/管理者/普通从业者视角”。

至少输出：

- 目标：现在最应该保护或争取什么
- 选项：2-3 个可行动方案
- 判断：推荐哪一个，为什么
- 下一步：立刻可以执行的第一个动作
- 观察点：接下来要盯哪几个信号

常见错误：

- 建议过大、过空，无法执行
- 把“继续观察”当成唯一行动
- 建议和前面的分析脱节

## Quality Bar

在结束前，逐项自检：

- 事实和推测是否明确分开
- 原因是否已经穿透到驱动层，而不只是停在症状
- 系统归类是否给出依据，而不是只贴标签
- 影响是否覆盖了对象和传导路径
- 规律是否能迁移到类似事件
- 预测是否同时包含概率、触发条件、早期信号
- 决策是否具体到可以执行的下一步

如果用户只要简版，可以压缩字数，但不要删掉七步中的任一步。
